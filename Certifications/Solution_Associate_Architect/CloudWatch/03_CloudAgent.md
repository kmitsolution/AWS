# AWS CloudWatch Agent

## 1. Introduction

Amazon CloudWatch Agent is a software agent installed on EC2 instances or on-premises servers to collect system-level metrics and logs.

By default, Amazon CloudWatch provides basic EC2 metrics. However, to monitor operating-system-level information such as memory, disk space, swap, and custom logs, we need to install the CloudWatch Agent.

The CloudWatch Agent collects this information and sends it to Amazon CloudWatch under the **CWAgent namespace**.

Using CloudWatch Agent, we can:

- Monitor server health.
- Monitor memory and disk utilization.
- Collect application and system logs.
- Create alarms.
- Troubleshoot performance issues.

---

## 2. Why Do We Need CloudWatch Agent?

Let's understand the difference between default EC2 monitoring and OS-level monitoring.

### 2.1 Default EC2 Metrics

By default, EC2 provides basic monitoring metrics such as:

| Metric | Description |
|---|---|
| CPUUtilization | CPU utilization of the EC2 instance |
| NetworkIn | Incoming network traffic |
| NetworkOut | Outgoing network traffic |
| DiskReadOps | Number of disk read operations |
| DiskWriteOps | Number of disk write operations |
| StatusCheckFailed | Indicates whether an instance status check has failed |

These metrics help us understand the basic performance and health of an EC2 instance.

### 2.2 OS-Level Metrics

However, default EC2 monitoring does not provide important operating-system-level metrics such as:

| Metric | Description |
|---|---|
| Memory Usage | Memory utilization of the server |
| Disk Space Usage | Available and used disk space |
| Swap Usage | Swap space utilization |
| Process Monitoring | Monitoring running processes |
| Application Logs | Logs generated by applications |
| System Logs | Operating-system-level logs |
| Custom Logs | User-defined log files |

To collect these metrics and logs, we need to install the **Amazon CloudWatch Agent**.

### 2.3 Default EC2 Monitoring vs CloudWatch Agent

| Feature | Default EC2 Monitoring | CloudWatch Agent |
|---|---|---|
| CPU Utilization | Yes | Yes, if configured |
| Network In/Out | Yes | Can collect additional OS-level information |
| Disk Read/Write Operations | Yes | Can collect additional disk metrics |
| Memory Utilization | No | Yes |
| Disk Space Utilization | No | Yes |
| Swap Usage | No | Yes |
| Application Logs | No | Yes |
| System Logs | No | Yes |
| Custom Logs | No | Yes |

**Important:** CloudWatch Agent publishes collected metrics to CloudWatch under the CWAgent namespace.

## 3. Setup CloudWatch Agent

To configure CloudWatch Agent on an EC2 instance, we need to perform the following steps:

1. Create an IAM Role for EC2.
2. Attach the IAM Role to the EC2 instance.
3. Install and configure CloudWatch Agent.
4. Monitor memory metrics using CloudWatch.

---

## 4. Step 1: Create IAM Role for EC2

CloudWatch Agent needs appropriate permissions to communicate with AWS services and publish monitoring information.

### Procedure

1. Navigate to AWS Console.
2. Open IAM.
3. Select Roles.
4. Click Create Role.
5. Select AWS Service as the Trusted Entity.
6. Select EC2 as the Use Case.

### Attach IAM Policies

Attach the following two policies:

#### Policy 1: AmazonSSMManagedInstanceCore

**Purpose:** Allows the EC2 instance to communicate with AWS Systems Manager.

This policy is useful when managing and configuring the EC2 instance through Systems Manager.

#### Policy 2: CloudWatchAgentServerPolicy

**Purpose:** Allows the CloudWatch Agent running on EC2 to send metrics and logs to Amazon CloudWatch.

### IAM Role Summary

| IAM Policy | Purpose |
|---|---|
| AmazonSSMManagedInstanceCore | Allows EC2 to communicate with Systems Manager |
| CloudWatchAgentServerPolicy | Allows CloudWatch Agent to publish metrics and logs |

Give the role an appropriate name:

`EC2-CloudWatch-Agent-Role`

Click Create Role.

---

## 5. Step 2: Attach IAM Role to EC2

After creating the IAM Role, we need to attach it to our EC2 instance.

### Procedure

1. Navigate to EC2.
2. Select Instances.
3. Select your EC2 instance.
4. Click Actions.
5. Select Security.
6. Select Modify IAM Role.
7. Choose the role created in the previous step.
8. Click Update IAM Role.

The IAM Role is now associated with the EC2 instance.

If your lab or management setup requires it, restart the EC2 instance as shown in the lecture workflow. Attaching an IAM role generally does not require an EC2 reboot.

---

## 6. Step 3: Install and Configure CloudWatch Agent

Now we need to install and configure CloudWatch Agent inside the EC2 instance.

### Procedure

1. Navigate to CloudWatch.
2. Select Configure the CloudWatch Agent.
3. Make sure the SSM Agent is installed and available on the EC2 instance.
4. Select the EC2 instance.
5. Install the CloudWatch Agent.
6. Configure the CloudWatch Agent.

The CloudWatch Agent collects operating-system-level information and sends it to Amazon CloudWatch.

**Note:** The exact installation and configuration commands depend on the operating system and the metrics/logs you want to collect.

---

## 7. Step 4: Monitor Memory Metrics

After installing and configuring the CloudWatch Agent, we can view the collected metrics in CloudWatch.

### Procedure

1. Open AWS CloudWatch.
2. Navigate to Metrics.
3. Select All Metrics.
4. Select the CWAgent namespace.

You can now view the metrics published by CloudWatch Agent.

For example:

- Memory utilization
- Available memory
- Disk utilization
- Swap utilization

The metrics available depend on the CloudWatch Agent configuration.

### Important Concept: CWAgent Namespace

CloudWatch Agent publishes its collected metrics under:

`CWAgent`

This is different from the default EC2 metrics namespace.

| Namespace | Metrics |
|---|---|
| AWS/EC2 | CPUUtilization, NetworkIn, NetworkOut, etc. |
| CWAgent | Memory, disk, swap and other configured OS-level metrics |

---

## 8. Important Points to Remember

1. CloudWatch Agent is software installed on EC2 or on-premises servers.
2. It collects system-level metrics and logs.
3. Default EC2 monitoring does not provide memory utilization.
4. CloudWatch Agent is required to collect OS-level memory metrics.
5. An IAM Role must be attached to EC2 to provide the required AWS permissions.
6. AmazonSSMManagedInstanceCore allows communication with Systems Manager.
7. CloudWatchAgentServerPolicy allows the agent to publish metrics and logs.
8. CloudWatch Agent publishes its metrics under the CWAgent namespace.

## 9. Interview Questions

**Q1. What is Amazon CloudWatch Agent?**

It is software installed on EC2 or on-premises servers to collect system-level metrics and logs.

**Q2. Why do we need CloudWatch Agent?**

To monitor operating-system-level metrics such as memory, disk space, swap, and to collect application and system logs.

**Q3. Can we monitor EC2 memory utilization using default CloudWatch metrics?**

No. We need to install and configure CloudWatch Agent.

**Q4. What is the CWAgent namespace?**

It is the CloudWatch namespace under which CloudWatch Agent publishes collected metrics.

**Q5. Which IAM policy allows CloudWatch Agent to send metrics and logs to CloudWatch?**

CloudWatchAgentServerPolicy.

**Q6. What is the purpose of AmazonSSMManagedInstanceCore?**

It allows an EC2 instance to communicate with AWS Systems Manager.

**Q7. Can CloudWatch Agent be installed on on-premises servers?**

Yes. CloudWatch Agent can be installed on EC2 instances as well as on-premises servers.

---

## 10. Conclusion

Amazon CloudWatch provides basic monitoring capabilities for EC2 instances.

However, when we need detailed operating-system-level monitoring, such as memory utilization, disk space, swap usage, and application logs, we need CloudWatch Agent.

The agent collects this information and publishes it to Amazon CloudWatch under the CWAgent namespace.

**Remember:**

- AWS/EC2 → Default EC2 metrics.
- CWAgent → Operating-system-level metrics collected by CloudWatch Agent.
